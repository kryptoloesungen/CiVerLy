Source Files
============
Most importantly, there are the source files in ``src/civerly``.
Many of those implement the class hierarchy for CiVerLy ciphers and the
infrastructure around modeling and solving.

The most important modules and their responsibilities are:

- ``component.py``:
  Implements the fundamental components (for example ``SBox_CVL``,
  ``LinearLayer_CVL``, ``ModAdd_CVL``, ``AND_CVL``) and their MILP/SAT
  modeling logic. The main entry point is the :class:`civerly.component.Component`
  base class and its concrete subclasses.
- ``cipher.py``:
  Defines the :class:`civerly.cipher.Cipher` base class representing a directed
  acyclic graph of components or sub-ciphers. Public methods such as
  ``add_subcipher()``, ``add_output()``, ``eval()`` and ``model()`` are the
  main way to build and analyse ciphers.
- ``sboxcipher.py``:
  Provides :class:`civerly.sboxcipher.SBoxCipher`, a restricted cipher class
  that only allows S-box based non-linear components and supports MILP
  modeling.
- ``wordbasedcipher.py``:
  Provides :class:`civerly.wordbasedcipher.WordBasedCipher`, a cipher class
  with a fixed word size that works with word-wise edges instead of bitwise
  edges and forms the basis for word-wise modeling.
- ``wordsboxcipher.py``:
  Defines :class:`civerly.wordsboxcipher.WordSBoxCipher`, combining the
  restrictions of ``WordBasedCipher`` and ``SBoxCipher`` to support word-wise
  MILP modeling for S-box based designs.
- ``aeslike.py``:
  Implements :class:`civerly.aeslike.AESlike`, a specialized cipher subclass
  for AES-like primitives with a rectangular state, S-box layers, MixColumn-like
  linear layers and permutation layers.
- ``addrx.py`` and ``andrx.py``:
  Provide :class:`civerly.addrx.AddRX` and :class:`civerly.andrx.AndRX`, cipher
  subclasses tailored to Add-Rotate-XOR and AND-Rotate-XOR designs that support
  SAT-based modeling of such ciphers.
- ``model_options.py``:
  Collects all modeling options and enums (for example
  :class:`civerly.model_options.CRYPTANALYSIS`,
  :class:`civerly.model_options.OPTIMIZATION`,
  :class:`civerly.model_options.GRANULARITY`) and the
  :class:`civerly.model_options.MODEL_OPTIONS` data class, which is the main
  configuration object passed to ``model()``.
- ``solvers.py``:
  Contains the glue code to interact with external MILP and SAT solvers.
  The main entry points are functions such as ``solve()``, ``optimize_sat()``,
  ``get_objective_value()`` and the :class:`civerly.solvers.SOLVING_STATUS`
  enum.
- ``trail.py``:
  Implements :class:`civerly.trail.TrailNode`, a helper class to represent and
  verify differential or linear trails in reports generated by CiVerLy.
- ``util.py``:
  Provides a collection of utility functions used throughout the library,
  including conversions between integers and bit vectors (``int_to_vec()``,
  ``vec_to_int()``) and helper routines for generating constraints and
  interacting with solvers.
- ``benchmark.py``:
  Contains the :func:`civerly.benchmark.benchmark` function, which generates
  benchmarks for different ciphers and model options and prints timing
  information (for example as LaTeX tables).
- ``cipher_implementations``:
  Contains the implementation of several well-known ciphers (for example AES,
  PRESENT, GIFT, SKINNY) and examples showing how these can be modeled with
  CiVerLy.


Doc Files

Project File

LICENSE

Nix
===
`Nix <https://nixos.org/>`_ is a package manager.
We use it to track all the dependencies of the CiVerLy project.
This is done in the ``flake.nix``.
The ``flake.lock`` contains hashes to pin all current versions.
