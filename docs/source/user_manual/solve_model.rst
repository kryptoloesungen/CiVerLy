=================
Solving the Model
=================

After CiVerLy modeled a cipher with SAT, the next step is to solve the model.
As depicted in the overview in :ref:`fig:workflow`, this is done using an external SAT solver.
Notice that this step is expected to be the most time consuming in the CiVerLy workflow.

To this end, for MILP, CiVerLy supports SCIP, GLPK, and Gurobi.
Notice that the first two are open source while Gurobi is a commercial product requiring a license to operate.
Although we obtained good results with SCIP, the general consensus in the cryptographic community is that commercial MILP solvers are considerably more efficient than the few open source options.
As CiVerLy relies on common standards to store MILPs, such can be used externally as well.
Here, we also want to point out that there are entities that solve MILPs as a service, see `NEOS Server <https://neos-server.org/neos/>`_.
However, we want to make it crystal clear that the models generated by CiVerLy might be traced back to (at least some information about) the cipher under scrutiny.

In contrast to MILP, for SAT there are many potent open source solvers available.
For this project, we agreed on tightly integrating CryptoMiniSat and CaDiCaL into CiVerLy.
As CiVerLy makes use of sage to store the generated SAT models in the standard DIMACS `format <https://doc.sagemath.org/html/en/reference/sat/sage/sat/solvers/dimacs.html#sage.sat.solvers.dimacs.DIMACS>`_, other solvers can be used externally as well.

Solving Externally
==================

If the used solver is installed on the same machine as CiVerLy, CiVerLy can directly use it and will do so when the ``cipher.analyse`` function is being used.
Of course, you can use CiVerLy also to only generate the models and then solve them externally, e.g., on a different machine.

MILP
----

For MILP, it suffices to run the ``cipher.model`` function to generate a MILP stored in a ``.mps`` file, a common format supported by MILP solvers.
This can then be fed into your solver of choice.
As mentioned before, solving the MILP is often expected to take a significant amount of time.
However, notice that most MILP solvers will report meaningful intermediate results.

Below, we exemplary depict the output of the three solvers SCIP, Gurobi and GLPK when solving a MILP for 10-round AES.
As this is a rather simple problem, SCIP and Gurobi finish nearly instantly, but for more complex problems the solvers will report the current state every few seconds.

Most importantly for us, this state contains the current bounds (both upper and lower) on the objective value, i.e., here the number of active S-boxes.
SCIP reports them as ``dualbound`` and ``primalbound``, Gurobi reports them as ``Incumbent`` and ``BestBd`` and GLPK simply states both of them with a ``>=`` between.
Notice that the actual values are sometimes reported in scientific notation, i.e., using e.g. ``e+01`` to indicate a factor of 10.

For bit-wise models, the objective value is the weight, i.e., the negative logarithm with base 2 of the probability, of the best found trail.
For word-wise models, the objective value is the number of active S-boxes.
Hence, from an attacker's view, the upper bound corresponds to the complexity of the best attack found so far.
On the other hand, the lower bound corresponds to a proof that no attack can use a trail with less active S-boxes (or a higher probability resp.) than given by the bound.
Therefore, these bounds can provide valuable insights on the security of the cipher under scrutiny (possibly long) *before* the solver terminates.

SAT
---

As SAT is a decision and not an optimization problem, we need multiple SAT instances to find an optimal trail.
To generate those, set the solver to ``None`` in the model options and then run the ``cipher.analyse`` function.
This will generate model that encode the question whether there exists a trail with weight less or equal `W` for all `W` in the solve range, i.e., for `0 \leq W < 100` per default.
You can tackle these SATs then with a SAT solver of you choice.
Every time you solve a problem, your bound improves.
That is, when you solve the problem for the weight bound `W`, you get either ``SAT`` or ``UNSAT``.
If the result is ``SAT``, this means that the optimal trail has weight less or equal `W`.
If the result is ``UNSAT``, this means that the optimal trail has weight greater than `W`.
